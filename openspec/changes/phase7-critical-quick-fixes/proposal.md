# Proposal: phase7-critical-quick-fixes

## Why

Аудит безопасности и стабильности от 2026-08-14 (`BUGS.md`, фаза 7 ROADMAP) выявил 5 критических уязвимостей. Блок 1 рекомендуемого плана работ — три быстрые изолированные правки максимального снижения риска: `C5` (порты `8080`/`5432` опубликованы наружу — обход nginx rate-limit и прямой доступ к БД), `C1` (фолбэк на mock-аутентификацию с захардкоженным паролем при недоступности БД — полный компрометирующий сценарий), `C3` (`/api/v1/auth/me` без middleware — всегда 401, сессия «не переживает» перезагрузку страницы; закрывает идею из `IDEAS.md`).

## What Changes

- **C5:** убрать публикацию хост-портов `5432` (postgres) и `8080` (storage-service) из `docker-compose.yml`; доступ только через `web-frontend`/`32214` внутри docker-сети.
- **C1:** сервис обязан падать (`log.Fatal`) при недоступной БД или пустом `POSTGRES_HOST`; `MockAuthService` с захардкоженными кредами полностью удаляется из production-кода; тесты переводятся на лёгкие тестовые double без реальных кредов.
- **C3:** роут `GET /api/v1/auth/me` оборачивается в `requireAuth`, при валидной сессии возвращает `200` с профилем, без сессии — `401`.
- Регрессионные тесты на каждый фикс согласно разделу «Обязательные регрессионные тесты» в `BUGS.md`.

### New Capabilities

(нет)

### Modified Capabilities

- `auth-multi-tenancy`: БД становится обязательной для старта (никаких mock-фолбэков и захардкоженных кредов); `GET /api/v1/auth/me` требует аутентификации и возвращает профиль пользователя при валидной сессии.
- `deployment-ci-cd`: контейнеры `postgres` и `storage-service` не публикуют хост-порты; весь внешний трафик идёт только через `web-frontend`.

## Impact

- Код: `services/storage-service/cmd/main.go` (startup, роуты), `internal/auth/service.go` (удаление `MockAuthService`), `*_test.go` (перевод с mock на test doubles, новые регрессионные тесты).
- Инфраструктура: `docker-compose.yml` (блоки `ports`), локальная отладка БД — только через `docker compose exec`.
- CI/CD: тестовые креды остаются только в `.github/workflows/ci.yml` (допустимо, тестовое окружение).
- Обратная совместимость: прямой доступ к `:8080` API и `:5432` БД с хоста перестаёт работать — ожидаемое поведение (security fix), приложение продолжает работать через `32214`/домен.
- Покрытие `internal/*` должно остаться ≥ 85% (удаление mock-кода и новые тесты).
