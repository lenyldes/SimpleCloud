# Proposal: phase7-db-metadata-quotas-deletion

## Why

Блок 2 Фазы 7 устраняет самый опасный кластер находок аудита `BUGS.md`: метаданные файлов живут только в памяти (C2 — потеря данных при рестарте + IDOR-скачивание чужих файлов), совокупная квота не контролируется (C4/M8 — переполнение диска как DoS), файлы невозможно удалить, а удаление папок оставляет файлы-сироты на диске (H4), ошибка парсинга `parent_id` молча игнорируется (M7). Основные specs (`file-storage`, `folder-management`) уже описывают целевое поведение — реализация ему не соответствует, и это изменение приводит код к спецификации.

## What Changes

- **BREAKING (внутренний API конструкторов):** `FileHandler` получает обязательный `*pgxpool.Pool`; `FolderHandler` — типизированный конструктор вместо variadic `args ...interface{}`. In-memory `maps` (`files`, `folders`) и мьютексы полностью удаляются (тикет C2).
- Метаданные файлов читаются и пишутся исключительно в PostgreSQL (`files`): `UploadHandler` делает `INSERT INTO files` (при ошибке — откат и удаление файла с диска), `DownloadHandler` и `ListHandler` читают из БД с жёсткой проверкой владельца: нет записи или чужой владелец → 404.
- Метаданные папок читаются из PostgreSQL (`folders`) во всех операциях `FolderHandler` (create/list/delete) — устранение dual-write и рассинхрона память/БД.
- Транзакционный учёт квоты: `SELECT used_bytes, quota_bytes FROM users ... FOR UPDATE` в одной транзакции с записью файла, предпроверка `Content-Length` сравнивается с **остатком** квоты (`quota - used`), `used_bytes` инкрементируется при загрузке (тикеты C4, M8).
- Новый эндпоинт `DELETE /api/v1/files/:id`: проверка владельца, удаление файла с диска, `DELETE FROM files`, декремент `used_bytes` с защитой от ухода в минус (тикет H4).
- Удаление папки (`DELETE /api/v1/folders/:id`) рекурсивно собирает все вложенные папки и файлы в одной SQL-транзакции, физически удаляет файлы с диска и корректирует `used_bytes` (тикет H4).
- Валидация UUID `parent_id` при создании папки: задан, но не парсится → 400 `invalid parent_id`; родитель существует и принадлежит пользователю — проверяется по БД (тикет M7).
- Регистрация роута `DELETE /api/v1/files/:id` в `cmd/main.go` без конфликта с `/api/v1/files/download/`.
- Регрессионные тесты по списку «Обязательные регрессионные тесты» из `BUGS.md` для C2, C4, H4 (+M7/M8 как части блоков).

## Capabilities

### New Capabilities

(нет)

### Modified Capabilities

- `file-storage`: метаданные файлов становятся персистентными в PostgreSQL с проверкой владельца на чтение; учёт квоты становится транзакционным и считается от остатка; добавляется удаление файла с освобождением квоты и места на диске.
- `folder-management`: метаданные папок читаются из PostgreSQL; `parent_id` валидируется как UUID; рекурсивное удаление папок физически удаляет вложенные файлы с диска и корректирует `used_bytes`.

## Impact

- **Код:** `services/storage-service/internal/handler/file.go`, `internal/handler/folder.go`, `cmd/main.go`; новые/обновлённые `*_test.go` в `internal/handler`.
- **БД:** используются существующие таблицы `users` (колонки `quota_bytes`/`used_bytes`), `files` (включая `folder_id` из миграции 000003), `folders`. Новая миграция не требуется; `UPDATE users SET used_bytes` — первое реальное использование колонки `used_bytes`.
- **API:** новый эндпоинт `DELETE /api/v1/files/:id`; поведение `GET /api/v1/files/download/:id`, `GET /api/v1/files`, `GET /api/v1/folders`, `POST /api/v1/folders` меняется с «после рестарта всё теряется» на персистентное.
- **Тесты:** существующие тесты `FileHandler`/`FolderHandler`, опирающиеся на in-memory состояние, будут переписаны `[TEST-AGENT]` под БД/stub-пул; интеграционные тесты используют локальный PostgreSQL (skip при недоступности — по текущему паттерну).
- **Затрагиваемые тикеты BUGS.md:** C2, C4, M8, H4, M7 — список для маркировки `✅` при архивировании утверждает `[AUDIT-AGENT]`.
