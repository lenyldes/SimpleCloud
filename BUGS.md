### 🟡 BUG-4: 2.5. Превью файлов: отсутствие детекции MIME-типов и поддержки Range-запросов (206 Partial Content)
- **Компонент:** Бэкенд (`services/storage-service/internal/handler/file.go:301-307`)
- **Серьёзность:** Medium / Core Feature (Превью файлов и стриминг медиа)
- **Связанный пункт чек-листа:** `2.5. Превью файлов`
- **Проявление:**
  - При скачивании/просмотре любого файла через `GET /api/v1/files/download/{id}` сервер безусловно устанавливает `Content-Type: application/octet-stream`. Из-за этого браузер не может отрендерить текстовые файлы, изображения и медиа в тегах `<img>`, `<video>` или `<audio>`, а скачивает их как бинарники.
  - При отправке заголовка `Range: bytes=0-10` сервер возвращает `200 OK` и всё тело целиком, вместо `206 Partial Content`, `Accept-Ranges: bytes` и `Content-Range`. Это ломает перемотку и стриминг видео/аудио в HTML5-плеере.
- **План исправления:**
  - Реализовать определение MIME-типа по расширению файла (через `mime.TypeByExtension`) или содержимому, с fallback на `application/octet-stream`.
  - Использовать `http.ServeContent` вместо `io.Copy(w, f)` для автоматической и стандартизированной поддержки Range-запросов (206 Partial Content), ETag и If-Modified-Since.

### 🟡 BUG-5: CSRF Origin Mismatch в Nginx Reverse Proxy при обращении через нестандартный порт (32214)
- **Компонент:** Nginx Reverse Proxy (`services/web-frontend/nginx.conf:42, 53`)
- **Серьёзность:** High / Security & Auth (Блокировка отправки форм из браузера)
- **Проявление:**
  - Браузер при запросах на `http://localhost:32214` шлет заголовок `Origin: http://localhost:32214`.
  - В `nginx.conf` настроено `proxy_set_header X-Forwarded-Host $host;`. Переменная `$host` в Nginx не содержит порт хоста.
  - Мидлварь `RequireSameOrigin` в Go сравнивает `u.Host` (`localhost:32214`) с `X-Forwarded-Host` (`localhost`) и возвращает `HTTP 403 Forbidden` (`{"error": "CSRF origin mismatch"}`).
- **План исправления:**
  - В `services/web-frontend/nginx.conf` заменить `$host` в заголовках `Host` и `X-Forwarded-Host` на `$http_host` (который сохраняет оригинальный порт клиента), либо добавить поддержку порта в Go middleware.

### 🟡 BUG-7: Полировка модальных окон (Escape, блокировка при запросе, фокус, XSS-защита, квота и токены тестов)

- **Серьёзность:** Medium / UX, Safety & Quality (Поведение модальных окон, защита от рассинхронизации и актуализация квоты)
- **Связанные пункты чек-листа:** `4.1.b`, `4.2.b`, `4.3.b`, `6.3`
- **Проявление:**
  1. **Escape не закрывает модалки (`app.js:274-278`):** Глобальный слушатель Escape обрабатывает только дропдаун профиля (`closeProfileDropdown()`). Модалки удаления, создания папок, превью файлов нажатие Escape игнорируют.
  2. **Гонка закрытия при сетевом запросе (`app.js:327-365`):** При клике на "Delete" кнопка подтверждения блокируется, но кнопка "Cancel", крестик "✕" и клик по оверлею остаются активными.   3. **Отсутствие фокуса на безопасной кнопке (`modals.js:197-216`):** При открытии окна подтверждения фокус остаётся на кнопке корзины в таблице, случайное нажатие Space/Enter может сработать непредвиденно.
  4. **Потенциальный риск XSS через innerHTML (`modals.js:209-211`):** Имя файла экранируется через `escapeHtml()`, но архитектурно безопаснее использовать контейнер `<span id="confirm-delete-target-name"></span>` и присваивать имя через `.textContent`.

  8. **Актуализация квоты в сайдбаре (`ui.js:122-126`):** Шкала `used_bytes` не опрашивает `/api/v1/auth/me` после успешной загрузки или удаления файлов без перезагрузки страницы (F5).
- **План исправления:**
  1. Реализовать централизованное закрытие активной модалки по клавише Escape в `app.js` (с учётом флага активности сетевых операций).
  2. В `handleConfirmDelete` блокировать крестик, кнопку Cancel и клик по оверлею на время выполнения запроса (свойство `disabled` / флаг `isDeleting`).
  3. При открытии `openConfirmDeleteModal` переводить фокус на кнопку Cancel (`confirmDeleteCancel.focus()`).
  4. В `index.html` и `modals.js` выделить `confirm-delete-target-name` и устанавливать имя через `.textContent`.
  5. Оформить класс `.confirm-delete-folder-warning` в `css/modals.css`.
  6. Добавить атрибуты `role="dialog"`, `aria-modal="true"`, `aria-labelledby="confirm-delete-title"` и `type="button"` в `index.html`.
  7. В `web_test.go` расширить/уточнить проверки вызовов API удаления в `app.js`.
  8. В `loadWorkspaceData()` (или обработчиках загрузки/удаления) запрашивать актуальные данные пользователя через `GET /api/v1/auth/me` и обновлять `state.user.used_bytes` перед перерисовкой квоты.

### 🟡 BUG-10: Two-Phase Quota, сокращение транзакции загрузки до 1-3 мс и санитарная валидация бэкенда
- **Компонент:** Бэкенд (`services/storage-service/internal/handler`: `file_upload.go`, `folder.go`, `file_upload_test.go`)
- **Серьёзность:** Medium / Performance & Reliability (Устранение блокировки пула соединений БД и валидация ввода)
- **Связанные пункты чек-листа:** `2.1`, `3.1`, `4.3.a`
- **Проявление:**
  1. **Удержание транзакции БД на время сетевого I/O (`file_upload.go:47-87`):** Вызов `tx.Begin()` и эксклюзивная блокировка строки `SELECT ... FOR UPDATE` выполняются до `r.ParseMultipartForm(32 << 20)` и `fh.engine.Save()`. При медленных клиентах или больших файлах соединение PostgreSQL удерживается открытым в транзакции десятки секунд, создавая риск исчерпания пула соединений (connection pool exhaustion).
  2. **Отсутствие проверки длины имени файла (`file_upload.go:174`):** При передаче имени файла длиннее 255 символов сервер падает на уровне PostgreSQL `500 Internal Server Error`, вместо возврата клиенту понятного `400 Bad Request`.
  3. **Отсутствие проверки на нулевой байт в имени папки (`folder.go:73-85`):** Имя создаваемой папки не проверяется на отсутствие символа `\x00`.
  4. **Компенсационное удаление сироты без логирования (`file_upload.go:180`):** При падении SQL-инсерта или коммита транзакции ошибка вызова `os.Remove(storagePath)` подавляется без логирования.
  5. **Утечка временных файлов в тестах (`file_upload_test.go:221-248`):** В утилите `createMultipartRequestWithDiskTempFile` отсутствует `t.Cleanup`, из-за чего при падении теста временный файл в `/tmp` может остаться неудалённым.
- **План исправления:**
  1. Реализовать двухфазную модель проверки квоты (Two-Phase Quota Pattern): предварительная проверка квоты и чтение/сохранение файла на диск до `tx.Begin()`, затем короткая атомарная транзакция (1–3 мс) с `SELECT ... FOR UPDATE`, финальной проверкой квоты, записью метаданных в `files` и обновлением `used_bytes`. При превышении квоты — откат транзакции, удаление файла с диска и возврат `413 Request Entity Too Large`.
  2. Добавить валидацию `len(header.Filename) > 255` с возвратом `400 Bad Request`.
  3. Добавить проверку `strings.Contains(trimmedName, "\x00")` в валидатор имени папки в `folder.go`.
  4. Добавить логирование ошибок при компенсационном удалении: `if err := os.Remove(storagePath); err != nil { log.Printf(...) }`.
  5. Добавить `t.Cleanup(func() { _ = os.Remove(tempFilePath) })` в `file_upload_test.go`.

### 🟡 BUG-11: Декомпозиция роутера (риск лимита 450 строк), сохранение хэша папки при 401 и trailing slash
- **Компонент:** Веб-интерфейс (`services/web-frontend/src`: `app.js`, выделяемый `router.js`, `index.html`)
- **Серьёзность:** Medium / Frontend Architecture & Navigation (Предотвращение превышения лимита строк и сохранение Deeplink)
- **Связанные пункты чек-листа:** `1.3`, `3.2`, `5.1`
- **Проявление:**
  1. **Риск превышения универсального лимита <= 450 строк (`app.js`):** Файл `app.js` насчитывает 444 строки (запас всего 6 строк). Следующее расширение логики приведёт к падению CI-теста `TestMaxFileLineCount`.
  2. **Сброс хэша папки неавторизованного пользователя (`app.js:105-128`):** При открытии прямой ссылки `#/folder/<id>` неавторизованным пользователем `handleRoute()` вызывается до завершения логина, получает 401 Unauthorized от `/api/v1/folders?all=true`, ошибочно считает папку несуществующей, выводит тост об ошибке доступа и принудительно затирает адрес в `#/`. После логина целевой путь утерян.
  3. **Чувствительность к завершающему слэшу (`app.js:107`):** Регулярное выражение роутера `^#\/folder\/([a-zA-Z0-9-]+)$` не поддерживает опциональный слэш на конце (`/#/folder/<id>/`).
- **План исправления:**
