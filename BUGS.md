## 📋 Чек-лист ручного тестирования (User Smoke Checklist)

Отмечайте пройденные проверки символом `[x]`. Если при проверке какого-то пункта обнаружен баг — оставьте пункт пустым `[ ]` и опишите проблему в секции **"Найденные баги"** ниже.

### 1. Авторизация и сессии
- [x] **1.1. Вход в систему:** Успешный вход по логину и паролю `admin` (или данным из `.env`).
- [x] **1.2. Неверный пароль:** При вводе неверного пароля отображается понятная ошибка, вход блокируется.
- [x] **1.3. Сохранение сессии (F5):** После входа и перезагрузки страницы сессия сохраняется, модальное окно авторизации не выскакивает.
- [x] **1.4. Выход (Logout):** При нажатии на кнопку выхода сессия сбрасывается, доступ к файлам блокируется, открывается окно входа.

### 2. Загрузка, скачивание и просмотр файлов
- [x] **2.1. Загрузка через кнопку:** Нажатие на кнопку «Загрузить файл» открывает системный диалог, файл успешно загружается и появляется в списке.
- [x] **2.2. Загрузка Drag-and-Drop:** Перетаскивание файла мышью в окно браузера подсвечивает область и успешно загружает файл.
- [x] **2.3. Имена файлов с кириллицей и пробелами:** Загрузка файла с русским именем (например, `Тестовый Документ 2026.pdf`) проходит успешно, имя отображается корректно. *(Подтверждено автотестом Subagent A)*
- [x] **2.4. Скачивание файла:** При скачивании файл загружается на компьютер с оригинальным именем и расширением. *(Подтверждено автотестом Subagent A: RFC 5987 / SHA256 100% совпадение)*
- [ ] **2.5. Превью файлов:** 
  - [ ] Текстовые файлы (`.txt`, `.md`, `.json`, `.log`) открываются для просмотра. *(Сбой: сервер отдает application/octet-stream, см. BUG-4)*
  - [ ] Изображения (`.png`, `.jpg`, `.svg`) открываются в окне превью. *(Сбой: сервер отдает application/octet-stream, см. BUG-4)*
  - [ ] Видео / Аудио воспроизводятся (если применимо). *(Сбой: нет 206 Partial Content / Range, см. BUG-4)*

### 3. Папки и навигация
- [x] **3.1. Создание папки:** Создание новой папки с произвольным именем (включая пробелы и русские буквы). *(Подтверждено автотестом Subagent B)*
- [x] **3.2. Навигация вглубь:** Клик по папке открывает её содержимое, список файлов обновляется. *(Подтверждено автотестом Subagent B)*
- [x] **3.3. Вложенные папки:** Возможность создать подпапку внутри существующей папки (уровень вложенности 2+). *(Исправлено в fix-folder-navigation-bugs-8-9)*
- [x] **3.4. Хлебные крошки (Breadcrumbs):** Верхняя цепочка пути кликабельна и корректно возвращает на нужный уровень. *(Исправлено в fix-folder-navigation-bugs-8-9)*
- [x] **3.5. Загрузка файла в подпапку:** Файл, загруженный внутри подпапки, сохраняется именно в этой подпапке, а не в корне. *(Подтверждено автотестом Subagent B)*

### 4. Удаление и дисковые квоты
- **4.1. Удаление отдельного файла:**
  - [x] **4.1.a. API / Бэкенд:** Эндпоинт `DELETE /api/v1/files/:id` корректно удаляет файл из БД и физически стирает его с диска. *(Подтверждено автотестом Subagent C)*
  - [x] **4.1.b. UI интерфейс:** Наличие кнопки/иконки удаления файла на карточке и в таблице списка, диалог подтверждения, исчезновение файла из интерфейса. *(Исправлено в fix-ui-delete-controls-bug-6)*
- **4.2. Удаление непустой папки:**
  - [x] **4.2.a. API / Бэкенд:** Эндпоинт `DELETE /api/v1/folders/:id` каскадно удаляет папку и все вложенные файлы из БД и с диска. *(Подтверждено автотестом Subagent C)*
  - [x] **4.2.b. UI интерфейс:** Наличие кнопки/иконки удаления папки в интерфейсе, подтверждение каскадного удаления. *(Исправлено в fix-ui-delete-controls-bug-6)*
- **4.3. Обновление прогресс-бара квоты:**
  - [x] **4.3.a. API / Бэкенд:** Динамический побайтовый пересчет `used_bytes` в `/api/v1/auth/me`. *(Подтверждено автотестом Subagent C)*
  - [x] **4.3.b. UI интерфейс:** В сайдбаре шкала занятого места («X MB из Y GB») и проценты визуально пересчитываются после загрузки и после удаления файлов без перезагрузки F5. *(Исправлено в fix-modal-polish-and-quota-bug-7)*

### 5. Интерфейс, шрифты и адаптивность
- [ ] **5.1. Типографика и шрифты:** Текст отображается четким шрифтом Inter без артефактов и ошибок загрузки внешних шрифтов.
- [ ] **5.2. Режимы отображения:** Переключение между сеткой (плитка) и списком (таблица) работает корректно, раскладка не съезжает.
- [ ] **5.3. Адаптивность:** При сужении окна браузера или просмотре с мобильного устройства интерфейс не ломается, кнопки остаются доступными.

### 6. Элементы управления, тулбар и паритет функционала (UI Action Parity)
- [ ] **6.1. Живой поиск (Search):** Ввод в поле поиска шапки мгновенно фильтрует файлы и папки по названию. При очистке поля отображаются все элементы.
- [ ] **6.2. Сортировка файлов и папок (Sort By):** Переключение выпадающего списка «Sort by Name», «Sort by Size», «Sort by Date» правильно перестраивает порядок карточек и строк таблицы.
- [ ] **6.3. Кнопка «New Folder» в шапке:** Нажатие открывает модальное окно создания папки, поле ввода сразу в фокусе, создание срабатывает по Enter и клику «Create», окно закрывается по крестику / Cancel / Esc.
- [x] **6.4. Действия на карточках и строках (Actions):** 
  - На карточке в сетке (Grid) есть кнопки быстрого действия: Скачать, Удалить.
  - В таблице списка (List) в колонке «Actions» есть кнопки: Скачать, Удалить.
  - Клик по кнопке действия (скачать/удалить) НЕ приводит к открытию превью файла или переходу внутрь папки (`stopPropagation`).
- [ ] **6.5. Сайдбар навигации:** 
  - Пункт «All Files» активен по умолчанию.
  - Проверить реакцию на клик по пунктам «Favorites» и «Trash» (визуальный отклик / статус заглушки).

### 🟡 BUG-11: Декомпозиция роутера (лимит 450 строк), Deeplink при 401, послойный Escape и WCAG Focus Trap
- **Компонент:** Веб-интерфейс (`services/web-frontend/src`: `app.js`, `modals.js`, выделяемый `router.js`, `index.html`)
- **Серьёзность:** Medium / Frontend Architecture, Navigation & Accessibility
- **Связанные пункты чек-листа:** `1.3`, `3.2`, `5.1`, `6.4`
- **Проявление:**
  1. **Риск превышения универсального лимита <= 450 строк (`app.js`):** Файл `app.js` насчитывает 403 строки. Вынос роутера необходим для создания чистого запаса под модули и исключения риска падения CI-теста `TestMaxFileLineCount`.
  2. **Сброс хэша папки неавторизованного пользователя (`app.js:105-128`):** При открытии прямой ссылки `#/folder/<id>` неавторизованным пользователем `handleRoute()` вызывается до завершения логина, получает 401 Unauthorized от `/api/v1/folders?all=true`, ошибочно считает папку несуществующей, выводит тост об ошибке доступа и принудительно затирает адрес в `#/`. После логина целевой путь утерян.
  3. **Чувствительность к завершающему слэшу (`app.js:107`):** Регулярное выражение роутера `^#\/folder\/([a-zA-Z0-9-]+)$` не поддерживает опциональный слэш на конце (`/#/folder/<id>/`).
  4. **Безусловное закрытие меню профиля по Escape (`app.js:351-358`):** В глобальном обработчике `keydown` вызов `closeProfileDropdown()` выполняется безусловно вслед за `closeTopModal()`, закрывая меню профиля даже тогда, когда была закрыта верхняя модалка.
  5. **Отсутствие возврата фокуса при закрытии модалки (WCAG 2.1 Focus Trap, `modals.js`):** При открытии модалки удаления фокус переносится на кнопку «Cancel», но при закрытии окна фокус не возвращается на элемент-триггер (кнопку строки или карточки), дезориентируя пользователя клавиатурной навигации.
- **План исправления:**
  1. Вынести функции маршрутизации (`handleRoute`, `resetRoutingState`, отслеживание `hashchange`, хранение активного маршрута) из `app.js` в отдельный модуль `services/web-frontend/src/js/router.js` (~70 строк), сократив `app.js` до ~330 строк. Подключить `router.js` в `index.html`.
  2. В логике роутера проверять наличие сессии пользователя (`if (!state.user)`): не затирать хэш папки и не слать ложные тосты до авторизации, сохранять целевой маршрут и инициировать переход в `#/folder/<id>` сразу после успешной авторизации (`checkAuth()` / `login()`).
  3. Обновить регулярное выражение роутера для поддержки опционального завершающего слэша: `/^#\/folder\/([a-zA-Z0-9-]+)\/?$/`.
  4. В обработчике `keydown` в `app.js` сделать закрытие строго послойным: вызывать `closeProfileDropdown()` только если модальное окно не было закрыто (`if (!closeTopModal()) closeProfileDropdown();`).
  5. В `modals.js` при открытии модалки подтверждения запоминать `const triggerEl = document.activeElement;`, а при закрытии окна возвращать фокус на исходный элемент (`triggerEl?.focus()`).
