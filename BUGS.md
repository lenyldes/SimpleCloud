## 📋 Чек-лист ручного тестирования (User Smoke Checklist)

Отмечайте пройденные проверки символом `[x]`. Если при проверке какого-то пункта обнаружен баг — оставьте пункт пустым `[ ]` и опишите проблему в секции **"Найденные баги"** ниже.

### 1. Авторизация и сессии
- [x] **1.1. Вход в систему:** Успешный вход по логину и паролю `admin` (или данным из `.env`).
- [x] **1.2. Неверный пароль:** При вводе неверного пароля отображается понятная ошибка, вход блокируется.
- [x] **1.3. Сохранение сессии (F5):** После входа и перезагрузки страницы сессия сохраняется, модальное окно авторизации не выскакивает.
- [x] **1.4. Выход (Logout):** При нажатии на кнопку выхода сессия сбрасывается, доступ к файлам блокируется, открывается окно входа.

### 2. Загрузка, скачивание и просмотр файлов
- [-] **2.1. Загрузка через кнопку:** Нажатие на кнопку «Загрузить файл» открывает системный диалог, файл успешно загружается и появляется в списке.
- [-] **2.2. Загрузка Drag-and-Drop:** Перетаскивание файла мышью в окно браузера подсвечивает область и успешно загружает файл.
- [ ] **2.3. Имена файлов с кириллицей и пробелами:** Загрузка файла с русским именем (например, `Тестовый Документ 2026.pdf`) проходит успешно, имя отображается корректно.
- [ ] **2.4. Скачивание файла:** При скачивании файл загружается на компьютер с оригинальным именем и расширением.
- [ ] **2.5. Превью файлов:** 
  - [ ] Текстовые файлы (`.txt`, `.md`, `.json`, `.log`) открываются для просмотра.
  - [ ] Изображения (`.png`, `.jpg`, `.svg`) открываются в окне превью.
  - [ ] Видео / Аудио воспроизводятся (если применимо).

### 3. Папки и навигация
- [ ] **3.1. Создание папки:** Создание новой папки с произвольным именем (включая пробелы и русские буквы).
- [ ] **3.2. Навигация вглубь:** Клик по папке открывает её содержимое, список файлов обновляется.
- [ ] **3.3. Вложенные папки:** Возможность создать подпапку внутри существующей папки (уровень вложенности 2+).
- [ ] **3.4. Хлебные крошки (Breadcrumbs):** Верхняя цепочка пути (например: `Корень / Документы / 2026`) кликабельна и корректно возвращает на нужный уровень.
- [ ] **3.5. Загрузка файла в подпапку:** Файл, загруженный внутри подпапки, сохраняется именно в этой подпапке, а не в корне.

### 4. Удаление и дисковые квоты
- [ ] **4.1. Удаление отдельного файла:** Файл удаляется из списка, исчезает из интерфейса после подтверждения.
- [ ] **4.2. Удаление непустой папки:** Удаление папки, внутри которой есть файлы, удаляет и папку, и всё её содержимое (каскадная очистка).
- [ ] **4.3. Обновление прогресс-бара квоты:** В сайдбаре шкала занятого места («X MB из Y GB») корректно пересчитывается после загрузки и после удаления файлов.

### 5. Интерфейс, шрифты и адаптивность
- [ ] **5.1. Типографика и шрифты:** Текст отображается четким шрифтом Inter без артефактов и ошибок загрузки внешних шрифтов.
- [ ] **5.2. Режимы отображения:** Переключение между сеткой (плитка) и списком (таблица) работает корректно.
- [ ] **5.3. Адаптивность:** При сужении окна браузера или просмотре с мобильного устройства интерфейс не ломается, кнопки остаются доступными.

## 🐞 Реестр найденных багов (User Bug Reports)

Заполняйте эту форму для любых замеченных дефектов, ошибок или странностей в поведении интерфейса.

### ✅ BUG-1 (fix-logout-button, 2026-09-06): Отсутствие механизма и кнопки выхода (Logout) в веб-интерфейсе
- **Компонент:** Веб-интерфейс (`services/web-frontend`: `index.html`, `styles.css`, `app.js`)
- **Серьёзность:** Medium / Security UX (Невозможно завершить сессию на клиенте без ручной очистки Cookies в DevTools)
- **Связанный пункт чек-листа:** `1.4. Выход (Logout)`
- **Шаги воспроизведения:**
  1. Открыть `https://test-cloud.lenyldes.ru` (или `http://localhost:32214`) и войти в систему.
  2. Попытаться найти кнопку выхода (Logout) в шапке сайта, сайдбаре или в профиле пользователя.
  3. Кликнуть по аватару пользователя `#user-profile` в правом верхнем углу.
- **Ожидаемый результат:**
  - В правом верхнем углу по клику на аватар открывается выпадающее меню с информацией о текущем пользователе (email) и кнопкой «Выйти» (`#btn-logout`).
  - При клике на «Выйти» отправляется запрос `POST /api/v1/auth/logout`, сбрасывается сессионная cookie `session_id`, очищается клиентский стейт (`state.user = null`, `state.files = []`, `state.folders = []`), очищается рабочая область и отображается модальное окно авторизации.
- **Фактический результат:**
  - Кнопка выхода полностью отсутствует в интерфейсе.
  - Клик по аватару пользователя `#user-profile` не вызывает никаких действий (обработчик событий отсутствует).
  - Выйти из системы штатными средствами интерфейса невозможно.
- **Технический контекст и первопричина:**
  - **Бэкенд:** Эндпоинт `POST /api/v1/auth/logout` полностью реализован в `internal/auth/handler.go` (`LogoutHandler`), покрыт тестами в `handler_test.go`, удаляет сессию из PostgreSQL и очищает cookie `session_id`.
  - **Фронтенд:**
    1. `services/web-frontend/src/index.html:49-51`: контейнер `#user-profile` содержит только `<div class="avatar" id="user-avatar">U</div>`. Выпадающее меню отсутствует.
    2. `services/web-frontend/src/styles.css:228-236`: класс `.user-profile` размечен как `/* User Profile Menu */` с `cursor: pointer`, но стилей дропдауна нет.
    3. `services/web-frontend/src/app.js`: поиск по `logout` даёт 0 совпадений. Нет функции `handleLogout` и нет слушателя клика по аватару.
- **План исправления (OpenSpec Scope):**
  1. **HTML:** Добавить блок выпадающего меню `#profile-dropdown` внутри `#user-profile` с отображением email пользователя и кнопки `#btn-logout`.
  2. **CSS:** Стилизовать `.profile-dropdown` (абсолютное позиционирование, `z-index`, тени, скругления, подсветка при hover, стрелка-шеврон).
  3. **JS:** Добавить открытие/закрытие дропдауна (включая закрытие по клику вне меню) и функцию `handleLogout()` с вызовом `POST /api/v1/auth/logout`, сбросом стейта, показом окна авторизации и toast-уведомлением.
  4. **Тесты:** В `frontend_integration_test.go` добавить проверки на присутствие `#btn-logout` в HTML и эндпоинта `/api/v1/auth/logout` в `app.js`.
